# Introduction

This is a summary of the week 1 introduction lesson.

## What this course is

We'll take our first serious steps in web application development. You learn to design, build and deliver a full-stack web application: an interactive frontend, your own backend API with a database, and the connection between the two.

We start with the fundamentals, and then move to a stack of current frontend and backend frameworks. Along the way you pick up the programming paradigms that come with them, and you learn to apply best practices.

Most lessons have a workshop part and a project part. In the workshop we introduce the theory and then practise it in a demo application. In the project part you apply the same thing to your group project, which will be a realistic web application built around a case. You and your team will work on this project all semester.

## What we use

- Both tracks build the same kind of application with a different stack. On the frontend, a component-based framework with TypeScript. On the backend, a server-side framework with an ORM and a database. One track uses React with ASP.NET Core and C#. The other uses Vue with Express and Node.js. Both are stacks that are relevant today.

- Frameworks come and go. What sits underneath them moves a lot slower, which is why the first weeks are about the fundamentals, HTML, CSS and the browser, before we touch a framework at all.

- Your track's lessons show the technology and the patterns we want you to build with. Other frameworks or languages are not allowed.

## Using the lesson material

The lesson text, provided every week in the Github repo, stays useful after the lesson ends. For example: We start with HTML and CSS in the first weeks, but you will need this later as well, when you add new components. You go back to that lesson and read the relevant part again.

## The planning and not working ahead

The topics per week apply to the group project too. The order exists so that you never learn something you have to unlearn later, which is why **working ahead is not allowed**. It's important that you get some practice with all of the subjects in this course, and we also want to prevent you from forming wrong habits. So also: don't start on the backend with your team before week 8.

## What we expect from you

12 credits is 336 hours. We expect the end result to be a realistic amount of work for that amount of hours. Outside the scheduled lessons, plan on roughly 10 hours a week on the project and 2 hours of self-study, plus the exam and presentation preparation.

Students who only work on their project during class hours will fall behind quickly. 

## Attendance

Attendance is mandatory. 6 absences (3 for the parttime course) over the whole course is the maximum, and that includes: illness, doctor's appointments, driving tests, etc. Arriving after the scheduled start time counts as absent.

Go over six and you get an ND, which means the course cannot be completed this semester and you take it again the next time it runs.

If during this semester you get the flu or a cold, you will probably need most of those allowed absences, so don't think too lightly of this.

## Generative AI

The rule is short. You do not use GenAI to generate your code or your documentation. It's fine to use it to figure out a concept you're stuck on, to produce a pile of seed data, or to work out what a compiler error is trying to tell you. Having it write your work is not, and you risk an ND.

Your brain is very good at saving energy. When code appears from GenAI and it seems to work, nothing is pushing you to find out why it works, so you don't, and next time you meet the same problem you're back where you started. _You_ need to be the one struggling to figure things out and not give up, before your brain actually stores that as work experience! We're only trying to help you do this.

## Getting started with your team

Before the first lesson, make working agreements together. Decide and set up how you communicate, when you meet outside class, what you do when someone goes off the radar for a week.

Put this into writing, and share it with your teacher next week.
